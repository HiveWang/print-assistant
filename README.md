# 打印助手

面向办公内网部署的批量打印网页。用户可一次选择 Word、PDF、JPEG、PNG
文件，指定网络打印机、黑白/彩色与份数，提交后查看转换、排队和打印状态。

## 已实现

- 批量选择或拖放文件，单次最多 50 个，单文件默认上限 100 MB。
- 自动发现 CUPS 网络打印队列，支持浏览器本机记忆默认打印机。
- 支持黑白/彩色、1–99 份；颜色使用 IPP 标准 `print-color-mode`。
- 每个浏览器会话使用独立随机 Cookie，任务和历史记录相互不可见。
- 全局打印队列支持多用户并发，默认同时处理 2 个任务。
- Word 由 LibreOffice 无界面转换为 PDF，随后交给 CUPS；PDF 和图片直接打印。
- 页面轮询展示上传、转换、打印和完成状态，并支持取消任务。
- 历史仅保留文件名、大小、打印设置和结果，不提供文件预览、下载或访问接口。
- 文件放在容器 `tmpfs` 中，任务结束立即删除；服务重启时再次清空。

## 一键部署

建议部署在能访问办公打印网络的 Linux 服务器上。服务器需安装 Docker Engine
和 Docker Compose 插件，并满足以下任一条件：

1. 服务器本机已配置 CUPS，`lpstat -p -d` 能看到打印机；或
2. 有一台允许该服务器访问的 CUPS 打印服务器。

运行：

```bash
./deploy.sh
```

部署脚本会自动识别 `/var/run/cups/cups.sock`。启动后访问：

```text
http://服务器IP:8080
```

需要修改端口、远程 CUPS 地址、队列位置或会话时长时：

```bash
cp .env.example .env
```

编辑 `.env` 后再次执行 `./deploy.sh` 即可。

## 打印机准备

本机 CUPS 模式下，可先在服务器确认：

```bash
lpstat -p -d
lpoptions -p <打印队列名> -l
```

若使用独立 CUPS 服务器，在 `.env` 中填写：

```text
CUPS_SERVER=10.10.10.20:631
```

部分老式打印机的驱动不识别 IPP 标准颜色参数；这种情况需在 CUPS 端把队列默认
颜色设置好，或在 `server/index.mjs` 的 `lp` 参数中补充厂商 PPD 对应选项。

## 数据与会话说明

- 文件内容只在任务处理期间存在于内存文件系统，成功、失败、取消都会进入清理流程。
- 历史记录保存在服务进程内存中，默认仅保留 8 小时无活动会话，服务重启后清空。
- 页面没有文件读取、预览或下载路由；历史列表也没有可点击的文件入口。
- 会话隔离不是账号鉴权：同一浏览器配置文件会共享会话 Cookie。共用电脑时请使用不同
  浏览器配置文件或无痕窗口。如需实名审计，可在内网网关前增加统一身份认证。
- “完成”以 CUPS 队列不再报告未完成任务为准；不同打印机未必提供逐页物理出纸进度。

## 常用维护

查看容器状态：

```bash
docker compose ps
```

查看打印服务日志：

```bash
docker compose logs -f api
```

停止服务：

```bash
docker compose down
```

## 本地开发

一个命令同时启动真实打印接口和网页：

```bash
npm run dev
```

开发预览端口为 `3000`，真实打印接口端口为 `8787`，网页会自动把 `/api/`
请求代理到本机接口。页面不会提供演示打印机或演示记录；CUPS 没有可用队列时会明确
显示“未发现打印机”。生产部署通过 Nginx 将接口与网页合并为同一内网入口。
